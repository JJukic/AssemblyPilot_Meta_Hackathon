# Meta SAM 3.1 segmentation

Muse Spark diagnoses assembly state; SAM locates visible objects. SAM never changes
`correct`, `incorrect`, `uncertain`, the correction instruction or Active Vision.
Inference remains Meta-hosted; there are no local model weights or additional agents.

- [Official API cookbook](https://github.com/meta-models/meta-model-cookbook/tree/main/07_sam/01_api_basics), including `sam_api.py` and `01_segment_image.py`

The requested developer-site pages ([overview](https://dev.meta.ai/docs/sam/overview),
[segmenting](https://dev.meta.ai/docs/sam/segmenting),
[client libraries](https://dev.meta.ai/docs/sam/client-libraries), and
[API basics](https://dev.meta.ai/docs/cookbook/sam-api-basics)) were blocked by the
cloud proxy (403). The official Meta GitHub sources above were accessible and used
instead. Provider/account limits and non-streaming support could not be independently
confirmed from those blocked pages. This client uses only the streaming image path
demonstrated in the official cookbook; it rejects unexpected non-streaming JSON.
Application limits below are local limits, not claims about Meta's maximums.

`meta-sam-parser==0.1.0` is the official, dependency-free Python package, pinned in
`pyproject.toml` and `uv.lock`. The model is constrained to `sam-3.1`. The same backend
`MODEL_API_KEY` authenticates both Meta clients. The endpoint guard rejects other
origins and redirects.

```json
{
  "model": "sam-3.1",
  "stream": true,
  "input": [{
    "type": "message",
    "role": "user",
    "content": [
      {"type": "input_text", "text": "green building block"},
      {"type": "input_image", "image_url": "data:image/jpeg;base64,..."}
    ]
  }]
}
```

This is POSTed to `https://api.meta.ai/v1/responses`. One concrete noun phrase is
used per concept request. For optional spatial mode, the official
`build_object_prompt` encodes a validated half-open pixel box for frame 0. Noun
phrases and object prompts are never combined. The official builder also documents
positive/negative points; this application does not expose point editing or video.

SSE framing is decoded as JSON events. The official `parse_responses_stream` handles
special tokens, lane identities, finalizers, refusals, incomplete responses and mask
codecs. Both `response.output_text.done` and `response.content_part.done` are supported.
Only a finalized, completed lane with no error diagnostics is accepted. An empty
completed lane means **zero matches**; missing/incomplete/invalid output is a failure.
No special-token regular expressions, aggregate-output fallbacks or fabricated data
are used. Optional confidence is not treated as correctness or used for selection.

## Coordinates and browser contract

`inspection_service.py` is the active orchestration boundary. It passes the **same
normalized JPEG bytes** to both models, then returns an inspection UUID, SHA-256
`snapshot_id`, exact JPEG/dimensions, original diagnosis, independent Muse timing,
and issue-indexed `segmentations` with independent SAM timings. These server fields
are not generated by either model. Existing SQLite data is unchanged.

SAM wire box corners are inclusive source-image pixels; the official parser converts
them to half-open bounds. Its mask is a **box-local raster**, not a full-frame mask.
The worker requires integer image bounds, matching crop/raster dimensions and a
nonempty decoded instance. The parser does not expose the wire's frame `w/h` as
record fields: the application checks all returned bounds against the actual request
image dimensions. It does not rescale output to an assumed model image size.

Each validated instance exposes `instance_id`, pixel `left/top`, and
`mask: {encoding: "png", width, height, data_url}`. The mask PNG is generated from the
officially decoded binary raster: red fill with alpha 90/255, boundary alpha 230/255,
transparent background. The bounding box is precisely `(left, top, mask.width,
mask.height)`; the browser divides these by snapshot dimensions for responsive
placement. No bounding geometry is inferred from prose.

The backend validates PNG type, dimensions, payload size, unique instance IDs,
image bounds and snapshot identity. The browser repeats structural/PNG-header checks,
checks the JPEG SHA-256 and displayed image dimensions, and hides masks whose decoded
size disagrees. It never accepts a mask URL from an external host. Historical Phase
3B responses without any SAM metadata remain readable.

The overlay offers **Show Segmentation** (mask versus boxes) and **Show original /
Show annotated**. It draws only the selected SAM instance; other candidates are kept
in the typed response for review but never highlighted arbitrarily. Issue labels,
fixes and localization status remain visible. Live video never receives overlays.
Completed history records retain their own snapshot and masks in tab memory, capped
at ten inspections; capture/step/project changes clear the current display.

## Routing, association and fallback

- Correct/uncertain diagnoses do not call SAM. Uncertain continues to request Active Vision.
- Missing parts never receive masks. Unknown issues are skipped.
- Misplaced/orientation issues with a recognized registered color use `<color> building block`.
  The initial color vocabulary is intentionally small; registry labels are not instructions.
- If no reliable concept can be derived but Muse supplies a valid observed box, use
  the official box prompt. Wrong-color/unexpected issues use this spatial path; never
  search for the expected color of a wrongly colored part. Without a box, skip clearly.
- At most two localization operations run sequentially per inspection (configurable
  down to zero). There is no automatic refinement loop. Repeated concepts for distinct
  issues can consume both slots; there is no cache across inspections.
- With no hint, exactly one instance may be selected. With a hint, selection requires
  intersection-over-union >= 0.25 and a >= 0.15 lead over any other candidate. Even a
  single instance that contradicts the hint is ambiguous. These are conservative
  association heuristics, not calibrated confidence or semantic verification.
- Disabled, skipped, no-match, ambiguous and unavailable statuses preserve the original
  Muse diagnosis and valid Muse boxes. The UI explicitly identifies fallback boxes.
  SAM errors never convert an incorrect result into correct.

## Resource, timeout and cost limits

`SAM_ENABLED=true`, `SAM_REQUEST_TIMEOUT=60` (maximum 60), and
`SAM_MAX_CONCEPTS_PER_INSPECTION=2` (0–2) are backend settings. Set `SAM_ENABLED=false`
to use Muse alone. `META_SAM_MODEL` is fixed to `sam-3.1` until a compatible model is
explicitly integrated. There are no new frontend secrets.

Each SAM operation has a total deadline covering networking, backoff and decoding.
Up to three attempts are allowed for transient transport/429/500/502/503 failures;
authentication, request errors and upstream 504 are not retried. A Retry-After over
two seconds immediately returns fallback rather than retrying early. Thus two
localization operations can result in up to six HTTP attempts, with no unbounded
calls. Cancellation propagates and kills an active parser worker. Browser abort
cannot guarantee cancellation of work already running at Meta.

Application limits: normalized image <=1600px/edge, existing encoded-image/request
limits, SSE <=2 MiB / 10,000 events, <=32 instances, each PNG <=512 KiB,
combined base64 masks <=2 MiB per operation. The official codec has no resource
quotas, so it runs in a short-lived subprocess with 512 MiB address space, 30 CPU
seconds and 35 seconds wall time, inside the overall SAM deadline. The worker receives
no API credential, does not log raw output and is killed on timeout/cancellation.
This worker requires POSIX resource limits (Linux/macOS); unsupported platforms safely
report SAM unavailable. Large/complex masks may exceed these conservative limits.

Muse retains its own deadline (default 60s, maximum 180s). The browser allows 310s
for the configured worst case of Muse + two SAM operations. Latency can be materially
higher than Muse alone. Each operation/retry may incur provider charges; check current
Meta dashboard pricing. No pricing figures or localization quality claims are assumed.

## Live validation

Normal tests use only synthetic images and injected HTTP transport. This explicit
command sends a potentially billable request using a photograph **you supply**:

```sh
cd backend
uv run --frozen python smoke_segmentation.py \
  --image /absolute/path/to/your-photo.jpg \
  --output data/sam-smoke/annotated.png
```

It always uses `green building block`, the existing safe normalization, real SAM,
the official parser and the same geometry checks. It prints instance count, duration,
identity and output path after a successful completed response, including zero matches.
All returned instances are annotated and labelled for manual review; this standalone
output is not an assembly diagnosis. Existing files are never overwritten. Missing
credentials/disabled SAM exits 77; failures exit 1. Input/output are never automatically
committed. The default output directory is Git-ignored.

Settings automatically reads `backend/.env` and process environment. A separately
named `.env.backend` is **not** automatically loaded; if that is your local filename,
use `uv run --env-file .env.backend --frozen python smoke_segmentation.py ...`.
Never put the key in a command argument or frontend variable.

Actual live status and executed checks are recorded in [validation.md](validation.md).
The next acceptance step is real-photo validation of correct/incorrect assemblies,
multiple identical blocks, occlusion and mask alignment. SAM segments visible shapes;
it does not independently understand the assembly specification or verify a repair.
